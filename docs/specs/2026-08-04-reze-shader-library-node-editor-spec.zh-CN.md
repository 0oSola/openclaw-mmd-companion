# Reze 着色器图库与节点编辑器规格

日期：2026-08-04

状态：已规格化，待按独立实施票据推进

关联输入：

- Reze 着色器图库、快速切换与节点编辑器交接；
- Reze Design 舞台配置概念；
- Reze 着色器工作流概念；
- 当前系统拓扑；
- Reze 着色器图库数据契约。

## 问题陈述（Problem Statement）

当前 Reze 材质编辑能力已经能读取 PMX 材质、显示部分样式组，并把少量中文预设应用到 Three.js 或 WebGPU 运行时，但它还不是一套可靠、可扩展的着色器工作流。

从用户视角看，主要问题是：

1. 样式组只有 Body、Eye、Face、Hair、Smooth Cloth 和未分组，无法完整表达引擎已有的九类材质语义；
2. 样式组批量应用与单材质选择都被压平到 `materialPresets`，用户无法判断一个材质是在跟随组，还是被单独覆盖；
3. `默认`既可能被误解为继承，也可能表示真实 Principled BSDF 图，重置语义不清楚；
4. WebGPU 应用图时，页面在引擎异步编译完成前就更新勾选和场景存档，失败后可能出现舞台、界面与存档不一致；
5. 当前窄素材库不能筛选、查看拓扑、锁定应用目标或管理本地图；
6. 用户无法导入、导出、收藏或跨模型复用自定义图，也无法安全删除被场景引用的图；
7. 当前没有基于 `reze-engine` 公共 `ShaderGraph` 接口独立实现的节点编辑器；
8. 材质不能通过拖放或可访问菜单移动到其他类别，自动分类也会把丝袜误归到身体或皮肤；
9. 旧场景仍使用 v1 localStorage 数据；若直接更换字段或忽略旧键，会造成已有材质绑定不可逆丢失；
10. AGPL-3.0 的参考编辑器只能作为交互与视觉参考，当前项目必须在 MIT 许可的 `reze-engine` 公共接口上独立实现。

## 解决方案（Solution）

建立一套只面向 `reze-design` 与 `reze-k3` WebGPU 舞台的 Reze 着色器工作流：

- 使用完整九类标准材质类别和未分组组织 PMX 材质；
- 使用“样式组基线 + 单材质图覆盖 + 人工分组覆盖”三层模型；
- 在每个非空样式组标题提供快速选择器（QuickPick），在单材质检查器提供“跟随样式组”和任意图覆盖；
- 把完整图库放入舞台上方的大弹层，桌面使用筛选、卡片、详情三栏布局，窄屏降级为列表与详情两级页面；
- 把内置图作为只读清单，把本地图作为按 `userId` 隔离的 IndexedDB 用户资产；
- 场景文档升级到 v2，只保存稳定图引用和绑定关系，不复制图 JSON；
- 提供 JSON 导入/导出、收藏、复制、重命名、引用保护删除和跨模型复用；
- 独立实现由当前 40 种引擎节点驱动的可视化节点编辑器；
- 所有正式图应用统一经过异步应用事务：旧图持续渲染，只有最新请求编译成功后才更新舞台、界面和持久化；
- 通过显式 v1→v2 迁移保留旧 `materialPresets`，并将旧 `半透材质`迁移为`柔滑布料`；
- 保持场景灯光、相机、背景、模型、动作和两条 WebGPU 管线原有隔离语义不变。

## 用户故事（User Stories）

1. 作为 Reze 舞台用户，我希望看到完整九类材质类别和未分组，以便材质树与引擎内置图能力一致。
2. 作为中文用户，我希望类别和图名称显示为“中文（English）”，以便理解语义并与引擎或参考资料对应。
3. 作为模型调试者，我希望材质树默认只显示非空组，以便在材质较少的模型上减少无意义占位。
4. 作为模型调试者，我希望移动菜单始终列出九类与未分组，以便把材质移动到当前为空的类别。
5. 作为样式组用户，我希望在组标题打开快速选择器并选择任意内置图，以便连续试验整体材质风格。
6. 作为样式组用户，我希望快速选择器在选择后保持打开，以便连续比较多个图。
7. 作为样式组用户，我希望当前已提交图显示勾选，正在编译的候选显示独立状态，以便区分已生效与待提交。
8. 作为样式组用户，我希望切换组基线时保留已有单材质图覆盖，以便局部调节不被批量操作抹掉。
9. 作为单材质用户，我希望检查器第一项为“跟随样式组：中文（English）”，以便明确清除覆盖而不是选择默认图。
10. 作为单材质用户，我希望选择任意内置或本地图作为覆盖，以便一个组内的特殊材质可以使用不同图。
11. 作为单材质用户，我希望组标题显示覆盖数量，以便快速发现该组并非所有材质都跟随基线。
12. 作为单材质用户，我希望“重置此材质”清除图覆盖和临时显隐，但保留人工分组，以便恢复跟随当前组而不改变组织结构。
13. 作为场景用户，我希望“恢复全部默认”只恢复组推荐图并清除单材质覆盖和临时显隐，以便不丢失灯光、相机、背景和人工分组。
14. 作为材质整理者，我希望拖动材质到另一组，以便快速修正自动分类。
15. 作为键盘或辅助技术用户，我希望通过“移动到样式组…”菜单完成同一操作，以便不依赖拖放。
16. 作为材质整理者，我希望能把材质移到未分组，并能单独恢复自动分组，以便可逆地修正分类。
17. 作为丝袜材质用户，我希望丝袜名称提示优先于 body/skin 分类，以便丝袜不会再误归角色皮肤。
18. 作为已有场景用户，我希望升级后旧材质选择仍保留，以便无需重新配置模型。
19. 作为已有场景用户，我希望旧 `半透材质`明确迁移到`柔滑布料`并显示迁移数量，以便理解变化且不会误变成丝袜。
20. 作为图库用户，我希望从样式组快速选择器打开图库时，目标锁定为整个组，以便浏览期间不会误应用到单材质。
21. 作为图库用户，我希望从单材质检查器打开图库时，目标锁定为当前材质，以便应用按钮含义明确。
22. 作为图库用户，我希望从材质页顶部打开图库时默认使用当前材质，同时允许显式切换到所属组，以便快速选择正确作用范围。
23. 作为图库用户，我希望应用按钮写明目标名称和目标类型，以便在提交前确认将改变哪个对象。
24. 作为图库用户，我希望按内置或本地、类型、标签、收藏和搜索词筛选，以便在图数量增加后仍能快速定位。
25. 作为图库用户，我希望卡片显示由图 JSON 自动生成的节点拓扑缩略图，以便在不复制真实渲染图的情况下辨认结构。
26. 作为图库用户，我希望详情显示放大拓扑、节点数量、标签、说明、推荐类别和渲染元数据，以便判断图是否适合当前目标。
27. 作为窄屏用户，我希望图库降级为列表与详情两级页面，以便不依赖三栏宽度。
28. 作为矮窗口用户，我希望在 560px 高或更低视口仍可分别滚动材质树、图库列表和详情，以便控件不重叠且操作可达。
29. 作为自定义图用户，我希望从纯 `ShaderGraph` JSON 导入图，以便复用旧数据。
30. 作为自定义图用户，我希望旧纯图导入默认使用 `auto`渲染集成类别和`opaque`透明度模式，并提示我可以修改，以便导入结果可预测。
31. 作为自定义图用户，我希望导出标准资产 JSON，以便备份或在其他兼容工具中复用。
32. 作为多模型用户，我希望本地图可跨模型、`reze-design` 和 `reze-k3` 复用，以便不用重复创建同一图。
33. 作为多用户浏览器环境中的用户，我希望本地图与收藏按 `userId` 隔离，以便不会看到其他用户的本地资产。
34. 作为资产维护者，我希望删除被引用图时看到模型、管线、组或材质引用，并必须选择替代图，以便场景不会出现悬空绑定。
35. 作为节点编辑者，我希望从空模板或内置图复制创建草稿，以便内置图保持只读。
36. 作为节点编辑者，我希望打开已可应用的本地图时创建独立草稿，以便编辑过程不会改变其他场景正在使用的资产。
37. 作为节点编辑者，我希望添加、删除、移动、连接和断开当前注册表中的全部节点类型，以便完整编辑引擎支持的图。
38. 作为节点编辑者，我希望编辑节点输入值和暴露参数，以便调整图的常量与可调参数。
39. 作为节点编辑者，我希望缩放、平移和适应画布，以便浏览大型图。
40. 作为节点编辑者，我希望撤销和重做图编辑，以便安全试验。
41. 作为节点编辑者，我希望编辑后约 300ms 自动校验，并在问题节点上显示诊断，以便快速修正非法链接或参数。
42. 作为节点编辑者，我希望校验成功后异步编译临时预览，以便真实舞台展示当前草稿效果。
43. 作为节点编辑者，我希望编译失败时舞台保留上一个成功版本，以便错误不会让角色材质消失。
44. 作为节点编辑者，我希望关闭未应用的编辑器后舞台恢复进入前的图，同时草稿仍保留，以便预览不会变成隐式提交。
45. 作为节点编辑者，我希望使用“应用”或“应用并关闭”正式提交，以便明确控制绑定时机。
46. 作为快速试图用户，我希望连续选择产生的过期编译结果被丢弃，以便最后一次选择决定最终状态。
47. 作为错误排查者，我希望看到图结构、WGSL 或 WebGPU 管线诊断及节点定位，以便判断失败发生在哪一层。
48. 作为许可证维护者，我希望当前项目只依赖 MIT 许可的公共引擎接口并独立实现界面，以便不引入 AGPL 编辑器源码。
49. 作为发布负责人，我希望在真实生产构建中验证 `reze-design` 与 `reze-k3`，以便开发模式通过不会被误当成发布完成。
50. 作为项目维护者，我希望最终架构文档与稳定概念同步更新，以便后续代理和服务读取到实际运行系统，而不是只看到设计稿。

## 实现决策（Implementation Decisions）

### 1. 产品和领域边界

- 新工作流只在 `reze-design` 与 `reze-k3` 启用。`reze-npr` 继续使用 Three.js 材质调试，不声称支持 `ShaderGraph` 编译。
- 标准材质类别使用引擎已有的九类机器语义：默认、角色皮肤、眼睛、面部、头发、金属、粗糙布料、柔滑布料、丝袜，另加未分组。
- 类别与图选择解耦。类别提供推荐图，但任意图都可应用到任意目标。
- `默认`是可执行内置图；继承只由缺少单材质覆盖表达。
- 内置图只读。本地图和编辑草稿属于当前用户。
- 参考工程只用于交互和视觉观察，不复制或改写其组件源码。

### 2. 场景文档与绑定模型

- 场景文档升级为 v2，继续保存名称、场景参数、调色和背景。
- 新增样式组基线、单材质图覆盖和人工分组覆盖三个独立字段。
- PMX 材质键由运行时提供，场景层视为不透明稳定键，不解析 WebGPU 或 Three.js 的内部格式。
- 最终图解析顺序固定为：单材质图覆盖 → 显式组基线 → 标准类别推荐图 → 未分组中性回退。
- 会话级可见性、透明度和发光调试不进入 v2 场景文档。重置操作可以清除这些临时状态，但不把它们升级为持久契约。
- `reze-design` 与 `reze-k3` 继续按用户、模型和管线隔离场景文档。

### 3. v1→v2 迁移

- 只有在 v2 键不存在时才读取同一用户、模型和管线的 v1 键。
- v1 `materialPresets` 中每个有效条目迁移为单材质图覆盖。
- 旧 `默认`继续表示显式默认图覆盖，不解释为跟随样式组。
- 旧 `半透材质`迁移为`柔滑布料`，其他有效中文预设按同名内置图迁移。
- v2 保存成功后保留 v1 值，不执行删除或原地重写。
- 迁移或规范化失败时不写 v2，并提供明确错误；不能用空默认文档覆盖旧数据。

### 4. 图引用与本地图仓储

- 内置图引用使用稳定中文标识；本地图引用使用 `local:<uuid>`。
- 内置图清单来自当前项目对 `reze-engine` 九个公开预设图的静态清单，并保存中文名、英文名、推荐类别、`renderClass`和`alphaMode`元数据。
- 本地图资产存入 IndexedDB，按 `userId`查询；收藏作为独立用户记录，因而同时支持内置图和本地图。
- 编辑已有可应用图时创建新草稿 ID；草稿保存期间不会改变旧资产或其场景引用。
- 草稿只有在图校验和 GPU 编译成功、用户点击应用后，才转为可应用资产并写入当前目标绑定。
- 删除本地图前扫描当前用户全部 v2 场景文档。存在引用、无法解析的潜在引用文档或当前未提交编辑会话时，删除必须被阻断。

### 5. 异步应用事务

- 所有快速选择器、图库和节点编辑器的正式应用都调用同一个可等待接口，不再使用同步返回值伪装成功。
- 应用事务包含请求 ID、目标、图引用和目标世代号。
- 同一目标每次新请求递增世代号；只有返回时仍匹配最新世代的成功请求可以提交 UI 和场景文档。
- 编译期间保持现有引擎样式组安装，旧图继续渲染。
- 图结构或 WGSL 生成错误直接返回节点诊断；WebGPU 着色器模块或管线创建错误返回引擎诊断。
- 成功反馈必须包含图显示名、目标显示名和目标类型。
- 失败、过期、目标模型切换或目标材质消失都不写场景文档。
- 引擎应用成功但场景文档写入失败时，必须把舞台恢复到事务开始前的正式图，并把本次结果标记为存储失败，不能留下“只在当前画面生效”的半提交状态。

### 6. 引擎样式组映射

- 每个类别基线在引擎侧对应一个稳定的运行时样式组，包含没有单材质覆盖的组成员。
- 每个单材质图覆盖对应一个只声明该材质的运行时样式组。
- 人工移动材质时重算组成员；单材质覆盖组保持不变。
- 引擎运行时组 ID 必须满足其小写字母、数字、下划线和连字符约束，但该 ID 不写入场景文档。
- 图资产携带 `renderClass`和`alphaMode`，应用时使用图自己的渲染集成元数据，而不是由材质类别强制覆盖。

### 7. 快速选择器和材质树

- 每个非空组标题右侧显示快速选择器，列出九个内置图、当前勾选、编译中状态、“编辑图”和“浏览全部…”。
- 单材质检查器提供“跟随样式组”以及内置和本地图入口，不在每个材质叶后放置完整下拉。
- 组标题显示单材质图覆盖数量。
- 人工移动同时支持拖放和菜单；拖放只是增强路径，菜单是完整可访问路径。
- 自动分类规则使用专门顺序，丝袜提示优先于角色皮肤，金属和粗糙布料拥有独立类别。

### 8. 完整图库

- 图库是舞台上方的独立大弹层，不塞入窄编辑器 Dock。
- 桌面采用左侧筛选、中间卡片、右侧详情三栏；窄屏采用列表与详情两级页面。
- 图库目标在打开时锁定，并始终显示在标题和应用按钮中。用户只能通过显式目标切换控件改变目标。
- 拓扑缩略图和详情图由同一套确定性布局逻辑从 `ShaderGraph`生成；已有 `ui.position`时优先使用，没有时生成布局。
- 图库不保存真实渲染截图。实际视觉效果由弹层背后的 MMD 舞台实时预览。

### 9. 节点编辑器

- 节点目录由当前 `NODE_REGISTRY` 驱动。规格基线是 40 种节点，不硬编码数量；覆盖测试要求新增引擎节点时编辑器元数据同步失败。
- 编辑器支持节点、端口、链接、输入值、暴露参数、位置、缩放、平移、适应画布、撤销和重做。
- 引擎注册表负责机器插槽和转换规则；宿主补充中文名称、分类、控件和说明元数据。
- `validateGraph()`和`compileGraph()`是同步图处理；正式 GPU 模块和管线安装是异步操作。界面可使用任务包装保持状态模型一致，但不得误报引擎接口本身为异步。
- 编辑后 300ms 防抖触发校验。校验通过后才发起临时预览编译。
- 临时预览使用编辑器进入时保存的原绑定作为恢复点；关闭未应用恢复原绑定，草稿继续保存。
- “应用”提交并留在编辑器；“应用并关闭”提交后关闭；失败时两者都不改变正式绑定。

### 10. 状态与反馈

- 用户可见状态至少包括：空闲、校验中、编译中、已应用、失败、已被更新请求取代、目标失效。
- 失败诊断按图结构、WGSL、WebGPU 管线和目标失效分组；有 `nodeId`时必须定位并标记节点。
- v1 迁移显示迁移条目数和旧 `半透材质`替换数。
- JSON 导入显示采用的默认 `renderClass=auto`和`alphaMode=opaque`，并提供后续修改入口。

### 11. 恢复语义

- 组级“恢复推荐图”恢复标准类别推荐图；未分组没有推荐图，因此清除其显式组基线并回到中性回退。
- “重置此材质”删除单材质图覆盖并恢复临时显隐，不删除人工分组覆盖。
- “恢复自动分组”只删除当前材质的人工分组覆盖。
- “恢复全部默认”清除全部显式组基线、单材质图覆盖和临时显隐；保留人工分组、场景灯光、相机、背景、调色和模型选择。

### 12. 当前代码基线修正

- 当前引擎实际有 40 种节点类型，不再沿用 handoff 中“约 25 种”的旧计数。
- 当前内置图实际有九个，现有宿主只导入其中七个并保留旧 `半透材质`别名；实施必须补齐粗糙布料和丝袜，并移除新建路径中的旧别名。
- 当前系统拓扑对 `reze-design` 是否使用 WebGPU、画布是否透明存在历史段落冲突；本功能完成后的架构同步必须以真实运行代码和生产验证为准，不直接复制旧描述。

## 测试决策（Testing Decisions）

### 最高测试接缝

主验收只保留一条最高业务接缝：

> 用户从快速选择器、图库或节点编辑器发起图应用 → 舞台返回异步提交结果 → 已应用状态和场景文档只在最新成功结果后同步更新。

该接缝必须覆盖成功、失败和过期请求，且验证舞台、界面、持久化三者一致。测试只观察外部行为，不断言 React 内部 state、具体组件层级或引擎私有对象。

### 纯数据测试

- v1→v2 迁移覆盖全部旧预设、旧 `半透材质`、无效值、缺字段、v2 优先和 v1 保留。
- 最终图解析覆盖单材质覆盖、组基线、推荐图和未分组回退的优先级。
- 自动分类覆盖九类，尤其是丝袜优先于 body/skin。
- 重置操作覆盖互不清除的字段边界。
- JSON 导入覆盖标准资产包、纯 `ShaderGraph`、无效 JSON、未知节点、超限节点和参数。
- 本地图引用扫描覆盖多模型、双管线、损坏场景文档和替代删除。

### 引擎适配测试

- 使用可控制的引擎适配器验证成功、结构失败、WGSL 失败、管线失败、目标消失和世代过期。
- 验证失败时旧安装继续存在，场景文档写入函数未被调用。
- 验证组基线与单材质覆盖映射为互斥的引擎样式组声明。
- 验证图资产的 `renderClass`和`alphaMode`被原样传递。

### 节点编辑器测试

- 节点目录覆盖当前注册表全部 40 个键；引擎新增键而宿主缺元数据时测试失败。
- 只测试用户可见编辑行为：添加、删除、连接、断开、值修改、撤销、重做、保存草稿和恢复。
- 诊断测试使用引擎公共 `Diagnostic`，验证有 `nodeId`时节点被标记，无 `nodeId`时显示全局错误。
- 300ms 防抖使用可控计时器，验证中间编辑不会发起多余 GPU 编译。

### 浏览器端到端测试

- 复用当前 Playwright 的 Reze 编辑器入口和本地会话种子方式。
- 新增 v1 场景迁移、九类显示、组与材质快速选择、编译失败回退、最后一次选择优先、跨组移动、图库目标锁定、导入导出、引用保护删除、节点编辑与关闭恢复。
- 以 1280×720 验证桌面三栏，以窄屏验证两级页面，以不高于 560px 的视口验证独立滚动和控件可达。
- 对 `reze-design` 与 `reze-k3` 各运行至少一条真实 WebGPU 应用链路。

### 发布验证

- 运行基础检查、类型检查和生产构建。
- 启动生产服务并确认加载的是本次构建产物，不使用遗留开发服务或旧 bundle。
- 在真实 PMX 上验证九个内置图均可对任意非空组发起应用。
- 记录成功、失败回退和快速连续选择的实际界面证据。
- 只有生产模式下两条 WebGPU 管线通过端到端验收，才能表述为完整解决。

## 当前缺陷、待办与验收证据映射

| 当前缺陷 | 对应待办 | 必须提供的验收证据 |
|---|---|---|
| v1 只有 `materialPresets`，无法表达三层状态 | 场景文档 v2 与迁移 | 迁移测试、旧场景样例、v1 保留、v2 写入结果 |
| WebGPU 调用不等待异步编译 | 统一异步应用事务 | 失败不写存档、旧图继续渲染、最后一次选择优先 |
| 只有部分样式组和图 | 九类清单与自动分类 | 九类 UI、九个内置图、丝袜优先分类测试 |
| 组批量应用会压平单材质差异 | 组基线与单材质覆盖 | 切组基线后覆盖数量和单材质效果保持 |
| 无人工跨组移动 | 拖放、菜单与恢复自动分组 | 移动持久化、恢复自动分组、覆盖保留 |
| 素材库过窄且目标不明确 | 独立三栏图库 | 目标锁定按钮文案、三栏/窄屏截图、560px 回归 |
| 无用户级图资产 | IndexedDB 仓储与导入导出 | 跨模型复用、用户隔离、纯图导入默认元数据 |
| 删除图可能破坏场景 | 引用扫描与替代删除 | 多场景引用列表、阻断、替换后删除 |
| 无节点编辑器 | 独立画布和草稿生命周期 | 40 节点覆盖、撤销重做、草稿保留 |
| 预览失败可能污染正式绑定 | 防抖校验、临时预览与恢复 | 非法节点定位、失败保留上次成功图、关闭恢复 |
| 文档存在历史矛盾 | 最终拓扑和概念同步 | 真实生产代码、测试命令和文档 diff 一致 |

## 补充说明（Further Notes）

### 许可证边界

参考工程的快速选择器、材质侧栏和图数据仅用于理解行为、视觉层级和公开数据格式。实现必须从当前项目领域模型和 `reze-engine` 公共 schema 出发独立编写。代码评审应检查是否出现来自参考工程的组件结构、命名或大段相似实现。

### 规格阶段不做运行时承诺

本文和数据契约只确定行为、字段、边界和验收方式，不代表功能已经实现或验证。当前工作区已有 `reze-k3`、WebGPU PMX 文本长度补丁、材质滚动和相关文档的未提交改动；实施票据必须保留这些改动，并按项目规定从干净 base commit 创建独立短路径 worktree。

### 实施阶段边界

1. 先隔离领域状态和引擎适配接缝；
2. 再完成 v2 数据模型和迁移；
3. 建立异步应用事务；
4. 交付组与材质快速选择和完整分类；
5. 交付跨组移动；
6. 交付本地图资产的最小纵向路径；
7. 交付安全删除；
8. 扩展为完整图库；
9. 交付节点编辑画布；
10. 接入实时预览与正式应用；
11. 最后执行双管线生产验收和文档同步。

每个阶段都必须能独立验证，不把多阶段功能一次性压入单个大改动。
