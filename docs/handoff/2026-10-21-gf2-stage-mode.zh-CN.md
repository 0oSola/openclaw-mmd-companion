# Codex 会话交接：GF2 mode 正式舞台与加载优化

## 1. 本轮结果

正式网页 `http://127.0.0.1:3100/companion` 的 GF2 mode 使用克莱妲原皮捕获材质，保留v14d武器材质、六灯、描边和同步动作。GF2已与frontline共用房间背景和炭灰界面，角色画布透明。独立18748预览与正式舞台均使用无损资源包。正式GF2另补齐frontline的人形全息入场接线，并消除点击时重复检测多遍网格的卡顿。

## 2. 原问题与影响

独立预览的捕获渲染最初没有接入正式舞台。接入后用户Chrome等待很久才出现人物；用户随后确认最终能显示。原加载需要727次资源读取，加载及入场期间实体画布隐藏，状态文字位置也不利于观察。之前仅改透明画布没有同步frontline页面主题，本轮已补齐。

用户另指出缺少人形全息投影：原GF2虽然有普通粒子聚合和A03，但没有提供全息需要的预采样轮廓与相机投影；仅检查最终入场结束不能证明全息动画存在。

另发现人物点击递归遍历57份材质绘制副本：实际同一点检测约5263ms，仅检测原人物约93ms，真实页面鼠标输入也超时。修复前动作不一定丢失，但长时间主线程阻塞使交互像没有响应。

## 3. 根因

捕获贴图、着色程序、常量缓冲等以小文件分别经过网页代理，产生多轮请求；源资源接口要求重新验证。资源完成后仍需首次GPU绘制、粒子聚合与进场动作。实际日志证明模型与材质就绪、入场阶段切换，并非持续缺少模型；消息桥接401和扩展警告未被证明是渲染根因。

首轮打成5个大包时，当前浏览器的两个大条目未进入HTTP缓存，三个小条目命中；因此改用4MiB原字节分块。该现象不外推成所有Chrome固定大小限制。

## 4. 解决方式

- 模式值`gf2`绑定已验证PMX，比例0.08、原点不平移；准备线程保留附加UV，衣发形态准备先于多遍副本。共用VMD、镜头和交互生命周期。
- 人物保留26分区、脸部多遍、阴影、反射和颜色映射。正式透明输出使用实体覆盖率与预乘处理，不能把捕获辅助Alpha直接作为网页透明度。
- `gf2CapturedResourcePlan.js`由打包器和原文件对照共用；727份源文件约111.07MB，按4MiB切分、gzip无损压缩成27包约45.55MB。包名含内容摘要，清单版本2记录偏移，跨包文件还原为独立字节缓冲。
- 27包与1份清单合计28次读取，最多3路并行；包长期缓存，清单重新验证。正式资源由3100→8100提供，独立18748只承担自己的预览。
- 加载进度放在舞台上沿，直到入场结束；`stats.timings`区分资源墙钟、累计下载/解压、材质构造与首次绘制调用时间。

资源或依赖改变后执行：`node scripts/gf2/pack-captured-resources.mjs`。新包先生成，最后更新清单；旧内容摘要包不覆盖。

GF2现在提供同身份L06轮廓与当前相机投影。实际模型校验并建立后才提供其世界矩阵，避免0.08原比例误用frontline的旧拟合矩阵；材质加载期间即可显示全息。全息着色代码、几何、原动作不变。

GF2点击改为更新当前姿态包围球后只检测原人物，不遍历材质副本；绘制和原收藏动作规则保持。

## 5. 修改前后行为

刷新和重进GF2可复用同内容资源包；程序不会降贴图分辨率或省略环境反射。独立预览的`?resources=files`保留原文件对照路线。模式切换取消旧请求并释放绘制对象，缺失清单显示错误，重试入口可恢复。

正式GF2现在使用frontline房间背景、炭灰界面与透明画布。武器五分区、法线/粗糙度/金属度/遮蔽、渐变、环境反射、描边、六灯及显示开关保留；最终颜色统一GF2映射。

## 6. 验证结果

加载优化证据：`.scratch/gf2-render-research-20261020/stage-integration/optimization/`。全息返修证据位于同级`arrival/`，点击返修证据位于`click/`。

- `click/diagnosis.json`记录同点命中对照：57份副本递归检测5263.2ms，仅原人物92.7ms。修复后的`click/check-03/result.json`正式Chrome检查通过，命中134ms；真实鼠标依次播放两个不同收藏、动画推进、播放中不重启、完成恢复、背景/拖动排除，以及原武器/切换/资源恢复均通过。
- 实际用户IAB点击命中143.7ms；`click/actual-click-played.json`记录点击后真实收藏VMD返回played=true，时长7.67秒且动画时间已推进，截图`actual-click-played.png`。临时页面观测已移除，用户收藏与配置未修改。早期实际观测误盯applyInteraction，而VMD更新直接走playVmd；空记录不代表第二个产品缺陷。两个测试准备失败（设置按钮状态、相机方法名）原件保留，最终check-03通过。
- `arrival/check-02/result.json`：实际Chrome155的10项检查通过，包括材质清单暂缓时全息可见（49608个可见像素）、两个聚合进度97058个像素变化、全息→实体→A03→待机顺序、结束后移除投影画布，以及原人物/武器/旋转/切换/刷新/错误恢复。该检查人为暂缓真实资源，不作为性能计时。
- `arrival/actual-arrival.png`：实际已登录内置舞台显示人形全息；随后`actual-final-state.json`为GF2就绪、idle、投影画布数量0。主会话亲看全息与实体入场截图。`check-01`因测试解除请求拦截的时序错误中断，原件与原因保留；修正等待顺序后`check-02`通过，非产品错误。
- `bundle-byte-check.json`：727份解包结果与源文件逐字节一致。
- `preview-load-final/result.json`：未安装请求拦截，原文件727次请求，资源包28次；再次加载27包全部命中HTTP缓存。原文件资源准备893.5ms，资源包首次444.2ms，再次444.1ms（含解压）。全页分别6096/3300/3172ms，首次GPU绘制受编译缓存影响，不能把全部差额归因于资源包。
- 同机位原姿态对照：冷包8个RGB通道相差1/255，热包与原文件完全相同。保留`preview-load`缓存失败和`preview-load-02`严格逐字节像素断言失败原件；修订依据在原实施记录，未改写失败记录。
- `stage-full-02/result.json`：实际Chrome155、真实3100→8100资源，人物26分区、透明背景、frontline主题、真实动作、武器五分区/六灯/同步/开关、旋转、切换、刷新和缺失资源恢复7项通过；主会话亲看`gf2-motion.png`。选择模式到入场结束27449ms；最近有效旧版`chrome-final`为28734ms，较早一次为48768ms，不能声称稳定翻倍。
- 正式分段：模型4939ms、资源3683ms、构造155ms、首次绘制调用4349ms。并行下载累计10008ms不等于资源墙钟；首次绘制调用含同步编译/上传，不能当GPU纯耗时。
- 实际用户内置浏览器18748和已登录3100均刷新后正常显示；`actual-preview.png`、`actual-stage.png`及`actual-stage-state.json`记录本次页面。舞台资源准备939.6ms、模型1781.4ms，页面背景确认为frontline-room.jpg。旧长驻标签缺少最新CSS，刷新后生效。
- `preview-recovery/result.json`：独立首页清单缺失提示和按钮恢复通过。`cache-headers.json`确认正式代理转发长期缓存头和Range响应。
- 原8项模式/真实输入及14项API配置迁移结果保留，相关逻辑未变。原全项目类型错误与裸Node别名问题仍为既有范围，见上一版`types.log`、`node-tests.log`，不声明全项目检查通过。

## 7. 范围边界与遗留风险

完整入场仍约27秒；资源准备、模型准备、首次绘制及入场各有成本，本轮保留入场表现。不同机器、浏览器和代理负载可能改变用时；没有锁屏或认证事件专项结论。传统MME和Pet安装包未新增构建。

API更新为PID55348，8行共享配置逐项保留；18748更新为PID35364，3100 PID40144未重启。原PMX、VMD与捕获文件未改写，新增的是资源包。临时页面探针及写入端点已移除。分支与HEAD保持原值，加载优化摘要见`optimization/files.json`，全息返修摘要见`arrival/files.json`，点击返修最新摘要见`click/files.json`，未提交。
