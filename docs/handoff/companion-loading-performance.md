# Companion 加载阻塞与资源缓存优化

## 1. 本轮结果

3100真实页面已完成模型与材质初始化，不再停留在灰色加载态；配色、灯光、曝光和动作素材未修改。连续实测空缓存约14–16秒，再次加载约3.4–6秒。首次加载仍有48MB资源传输和浏览器初始化成本，不承诺秒开。

## 2. 原问题与影响

优化前3100文档约54毫秒返回，但8100清单、遮罩请求12秒无首字节，健康检查和不存在路径的404也5秒无响应。Python进程接近占满单核。两次非阻塞调用栈都停在聊天历史逐条补全动作解析记录的同步数据库查询中。

## 3. 根因

历史接口在async路由主线程执行同步读取；32条消息需要65条查询，动作解析表缺少匹配的复合索引并产生全表扫描及临时排序。实际数据库动作解析记录7865条，最大会话8433条消息。另一方面，V14D每个文件请求都会重新构建全量清单、重复读取模型和其他文件计算哈希；前端对固定资源使用no-store，无法复用浏览器缓存。

## 4. 修复

- 为动作解析与TTS查询增加workspace_id/message_id/排序字段复合索引。
- 历史关联数据按400条一组批量读取，保留全部消息、原排序与过滤规则；不分页截断、不删除聊天。
- 历史读取移至工作线程中的独立只读SQLite连接，使用只读事务快照，不共享业务写连接。桥接回声匹配按角色与规范化内容先分组，避免无关消息的两两比较。
- 清单与SHA缓存按文件大小、修改时间及创建时间失效，设置有界LRU；固定资源URL增加v=SHA256，版本匹配才发长期私有缓存。未带版本的文件使用ETag重新验证；源变动后的旧版本返回409。前端保留字节SHA校验，恢复标准缓存；PMX扩展名解析兼容查询参数。
- 网站图标复用已有14KB品牌图，消除/favicon.ico的404；没有新增图片资产。

## 5. 修改前后行为

32条消息从65条查询降至3条，返回对象逐字段相同。缓存测试中清单加五个遮罩请求只读取模型文件计算哈希一次，而非六次。文件修改、缺文件、旧版本、目录越界均仍会被检查。缓存不等于跳过客户端完整性校验。

## 6. 实际验证

- 新增回归初次5项失败，修复后8项全部通过。
- 前端相关21项测试通过，包含带v参数的PMX解析。
- 消息与桥接扩展测试71通过、1失败；同一动作素材匹配失败已在b7534a3的原Store代码中复现，未掩盖为通过。
- 真实历史接口返回7448条可见消息（原过滤规则），12.56MB，耗时0.503秒；同时健康请求约2–233毫秒，未出现原来的长时间阻塞。
- 8100重启后初次清单0.188秒、遮罩0.251秒、健康0.012秒。
- 浏览器无路由模拟、无资产存根。首次资源传输约48.01MB；复载观测范围约0.03–3.82MB。最后一次冷加载14.83秒、复载5.98秒，页面异常、控制台错误、材质资源失败均为0。
- 浏览器证据位于web/.scratch/companion-loading-1788894800441/report.json及cold/warm.png，前次观测亦保留。截图含本机页面内容，不作为公共发布资产。

## 7. 边界和失败记录

首次扩展测试入口导入全局app，新增索引可能已经在该阶段落到生产库；未插入测试聊天或删除用户数据。后续测试用API_DATA_DIR隔离。重启前通过SQLite backup做一致性备份，路径web/.scratch/performance-backup/trace-805f7aa809a8421db8087bf3ba6108cb.db，约1.38GB；该备份不宣称是加索引之前的版本。

主目录Playwright依赖存在模块/类型导出问题，全项目tsc因此未通过；实际浏览器验证只读复用已有独立工作树依赖，没有重装主项目依赖或忽略类型错误。一轮观测出现已有VMD字符解析提示，最后一轮未出现；本轮没有修改VMD解码。未跑完整生产构建或全量动作门禁。

## 8. 服务与数据保护

核对原8100进程的工作目录和命令后，以原命令、原环境重启，日志写入web/.scratch/performance-server/bcd2a05b61344e13ac5eb1d3bb913495。3100未重启，3142未改动。用户原有next-env及其他未跟踪文件不纳入本次提交。后端缓存仅支持正常文件变更失效，不承诺抵抗攻击者同时伪造内容与所有文件时间戳；重要资源的客户端SHA校验继续保留。
