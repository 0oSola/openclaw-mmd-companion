# 当前预览迁入 MMD 舞台：主会话接管修复

## 1. 本轮结果

新类型 v14d-game 已接入冻结预览的实际材质工厂、五张脸部遮罩、头发分区、六灯和本机 OCIO；增加舞台微调、按用户与模型隔离的本地保存及恢复截图默认值。不是重新美术调色，也不是游戏着色器等价证明。

## 2. 原问题与影响

子任务 ec23b45d 的 ready 状态并不代表外观迁移成功：交付截图为灰块，真实预览材质和脸部遮罩没有接入。头部裁切也妨碍验收。

## 3. 根因与修复

- 原 PMX 卡通材质不能替代源物理材质工厂；改为创建27个对应材质（其中20个物理材质），按源着色器解释 RMO 通道，不再仅挂属性。
- 源灯采用 power，旧代码把它当作 intensity。按模型缩放比例映射灯尺寸、位置和功率，保留辐亮度，并补模型平移；包含源的六盏灯。
- 服装颜色纹理必须按源预览使用 sRGB；恢复安装前色彩空间随释放执行。
- 新类型画布改用实际舞台宽高，避免准备态3:4覆盖画布导致裁头；其他类型不改。
- Windows资产目录大小写导致存在的 textures/extra.png 被白名单拒绝；保留目录白名单和路径越界拒绝，只对目录名比较忽略大小写。

## 4. 来源与生命周期

固定源提交 cd973980e08e09739d620cc948472638a4e1c7f2。v14dGameSource 中五个模块由该提交选择性迁入，不合并历史诊断分支。共享 MMDLoader、MMDAnimationHelper、VMD、相机、口型和物理入口继续沿用；新绘制钩子临时覆盖闭眼与微笑并 finally 恢复，说话时不盖掉嘴角源权重。销毁期间迟到材质不会挂回舞台。没有把参考姿态写入骨骼基线。

## 5. 参数及本机资源

默认本机OCIO、曝光-0.40、织纹2、纵向细线1、虹膜2、头发分区1、目标闭眼、微笑0.55、自动脸部阴影、六灯开启。外观面板可调整这些参数，手动遮罩仅关闭自动时使用；保存键按用户和模型隔离。内置AgX只是显式对照，不是缺资源时的静默替代。

本机准备：在web目录运行 node scripts/prepare-v14d-game-local-assets.mjs <现有预览的.scratch/v14d-head-preview目录>。只复制manifest、五mask、processor、GLSL及两LUT至当前web/.scratch/v14d-head-preview；校验已声明哈希，目标有不同内容时拒绝覆盖。API使用MMD_ROOT_DIR与V14D_GAME_ASSETS_ROOT（可选）定位本机资源。GLSL/LUT许可未确认，不进入public或发布包。

## 7. 失败记录和范围

验收准备先遇到存根缺字段、测试临时目录插件被仓库禁用、UI展开状态与选择器错误，均逐项修正；旧截图和检查点保留。Classic仍可能请求其原有无效spa/目录并404，本轮没有修改Classic资产策略。最终缺mask的404是预期负测，不算健康加载。

会话、配置和资源列表为浏览器隔离存根，PMX/VMD/纹理/遮罩/OCIO为真实本机字节；这不证明真实登录会话或生产后端联调。未跑完整动作生成门禁、长时间物理、跨GPU、全量历史回归或游戏逐像素对齐。新增参数视距变化的视觉效果也不等价跨场景标定。

## 8. 集成边界

主目录通过45a06954快进集成。其既有MMD_ROOT_DIR保持不变，新增本机V14D_GAME_MODEL_ROOT=D:/mmd单独定位该模式的模型；资源安全检查不允许目录联接越过根目录，因此运行改用明确根目录。本轮试建的MMD/克莱妲原皮联接清理命令被工具策略拒绝，联接仍保留且不供新模式使用，原D:/mmd资产未删除。缓存已准备在主目录Git忽略路径，用户next-env内容哈希保持不变。

源3142、原工作树与用户文件不动；本轮在独立工作树修复，构建生成的next-env/tsconfig变动恢复，不纳入功能提交。主工作区集成记录以最终Git操作为准。已完成本机工程迁移验证，不授予第三方资源再分发许可。
