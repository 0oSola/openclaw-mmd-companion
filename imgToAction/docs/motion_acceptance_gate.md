| 右肩臂角 | 0° | 170° | 30°-150° | T-pose=59.63° |

| 颈部前倾 | 0° | 30° | 0°-20° | 思考动作允许微低头 |

### 5.2 角度计算

肘角 = 上臂向量与下臂向量的夹角:
```
upper = shoulder_pos - elbow_pos
lower = wrist_pos - elbow_pos
elbow_angle = arccos(dot(upper, lower) / (|upper| * |lower|))
```

## G7 左臂约束

思考动作支持多种左臂语义。默认策略为 `down`，即右手单手思考、左臂自然下垂。对参考 VMD 或优雅思考动作，可显式使用 `support` 策略，允许左臂在腰/胸前做支撑或抱臂动作；如果动作定义要求左手叉腰，使用 `akimbo` 策略。

执行参数：

```bash
python imgToAction/tools/motion_acceptance_gate.py <joints.json> --source render --left-arm-policy down
python imgToAction/tools/motion_acceptance_gate.py <joints.json> --source render --left-arm-policy support
python imgToAction/tools/motion_acceptance_gate.py <joints.json> --source render --left-arm-policy akimbo
```

### G7.1 `down` 策略

| 检查项 | 阈值 | 说明 |
|---|---|---|
| 左手腕 Y < 左肩 Y | 始终满足 | 左手不举过肩 |
| 左手腕 X > 0 (PMX) | 始终满足 | 左手在身体左侧 |
| 左肘角度 | 150°-180° | 左臂自然伸直或微弯 |
| 左手腕前深度 | < 0.5 | 左手不前伸 |

### G7.2 `support` 策略

| 检查项 | 阈值 | 说明 |
|---|---|---|
| 左手腕 Y < 左肩 Y | 始终满足 | 左手不举过肩 |
| 左手腕 Y 范围 | 11.0-16.0 PMX | 保持在腰/胸前支撑区 |
| 左手腕前深度 | >= 0.0 | 支撑手不得跑到躯干后方 |
| 左肘角度 | 55°-150° | 允许弯肘支撑，但不允许完全折叠或异常伸直 |

例外: 如果 BVH 源动作本身左手有其它明确动作，可使用 `--left-arm-policy skip` 跳过 G7 语义检查，但不建议用于最终发布动作。

### G7.3 `akimbo` 策略

叉腰策略只检查稳定段 f150-f210，允许 f150 前从自然下垂过渡。该策略用于“右手思考 + 左手叉腰”的动作定义。

| 检查项 | 阈值 | 说明 |
|---|---|---|
| 左手腕 X | 2.0-2.65 PMX | 位于左腰外侧接触点 |
| 左手腕 Y | 13.0-13.95 PMX | 压在腰线，不落到髋/大腿侧 |
| 左手腕 Z | -1.25--0.55 PMX | 靠左腰侧前缘 |
| 左肘外张 | `left_elbow.x - left_wrist.x >= 1.0` | 形成清晰外张肘 |
| 左肘角 | 70°-120° | 接近 reference 叉腰肘角 |
| 左手轮廓模式 | `side_down` | 手指沿髋侧向下，禁止横向插入腰身 |
| 左手轮廓 Y | `min_y` 11.40-12.20；`max_y` 13.00-13.95 PMX | 手掌贴腰，指尖自然落到髋侧 |
| 指尖下垂量 | `wrist_y - min_hand_y` 1.20-2.20 PMX | 保留可见的向下指向，同时避免落到大腿 |
| 左手轮廓 X | `min_x` 1.45-2.05；`max_x` 2.00-2.70；跨度 <= 1.00 PMX | 整只手保持在身体左侧，不横跨腰部中心 |
| 左手轮廓 Z | `min_z >= -1.80` 且 `max_z <= -0.55` PMX | 整只手位于腰侧前缘安全带 |

2026-07-08 更新: 旧规则只看左腕和肘部，无法阻断“腕点在腰附近但手指/袖口位置错误”的假叉腰，因此加入左手指骨/指尖代理 bbox。

2026-07-14 更新: Blender 对优菈真实 PMX 变形网格的检查发现，旧 bbox 规则要求手指横向伸向身体中心，会让 v14 在稳定段产生 145 组三角面重叠却仍通过 G7。当前 strict `akimbo` 只接受 `side_down`：左腕贴腰、左肘外张、手指沿髋侧向下。v15 对 f0-f240 逐帧检查为 0 个碰撞帧，f160 最小净空 0.014774 PMX；`akimbo` 模式下任一 G7 违规均按 P0 阻断。

## G8 前深度保持

手腕在 raise 和 hold 阶段必须保持在躯干前方 (PMX 负 Z 方向)。

| 阶段 | 帧范围 | 右手腕 Z 要求 | 说明 |
|---|---|---|---|
| raise (抬手) | f0-f89 | Z < 0.0 | 手腕在身体前方 |
| hold (保持) | f90-f160 | Z < -0.5 | 手腕贴近脸/下巴前方 |
| release (放下) | f160-f196 | Z < 0.0 | 手腕在身体前方 |

前方轴投影计算 (PMX 模型空间, Z- = 前方):
`front_depth = dot(wrist_pos - torso_center, front_axis_pmx)`，front_axis_pmx = `(0, 0.14, -0.99)`，torso_center = `[0, 14, -0.5]`
正值 = 手腕在躯干前方 (正确), 负值 = 在后方 (穿模风险)

## G11 手部轮廓高度

思考动作中，G4 只检查右手腕到下巴的距离，不能覆盖手掌、指节、手套等视觉轮廓。G11 用右手腕 + 右手所有指骨/指尖的最高 Y 作为手部轮廓代理，防止“腕点正确但指节顶到脸上方”的假通过。

| 检查项 | 阈值 | 说明 |
|---|---|---|
| hold 阶段手部最高代理点 | `<= CHIN_SURFACE_Y - 0.25` | 下巴表面 Y=18.44，安全线 Y=18.19 |
| 参与骨骼 | 右手首 + 右親指/右人指/右中指/右薬指/右小指 0-3/指先 | 使用 `rendered_bone_frames.json` 的完整骨骼数据 |
| 数据不足 | FAIL | 最终验收不得只用主骨骼 JSON |

hold 阶段默认按 f110-f210 识别；如果动作时长不是 0-240 帧，需要同步扩展 `motion_acceptance_gate.py` 的 `_is_thinking_hold_frame()`。

## G12 右手托下巴语义

G11 只能证明手部轮廓没有顶到脸上方，不能证明右臂动作语义自然。G12 只检查稳定 hold 段 f150-f210，目标是阻断“腕点安全但右臂折叠/手不像托下巴”的假通过。

| 检查项 | 阈值 | 说明 |
|---|---|---|
| 右肘角 | 40°-90° | 小于 40° 会读成前臂硬折叠 |
| 右腕到下巴距离 | 1.8-2.6 PMX | 腕点不能直接贴脸，否则肩到腕距离过短导致折臂；也不能太远失去托下巴语义 |
| 最近右手轮廓点到下巴距离 | <= 0.85 PMX | 至少一个手指/掌部代理点要靠近下巴 |
| 右肘 X | -2.6--1.0 PMX | 防止右肘外翻到身体侧面造成硬折 |
| 参与骨骼 | 右肩/右肘/右腕 + 右手所有指骨/指尖 | 使用 `rendered_bone_frames.json` |

修复原则：优先调整右腕 IK 目标、右手首 Euler 和右手 finger profile。不要为了让腕点贴下巴而把右腕推入头部，也不要只靠放宽 G11。

## G13 右臂解剖学自然度

G12 证明动作读作“托下巴”，但仍可能通过“腕点安全 + 手指接触”掩盖右臂硬折叠。G13 只检查稳定 hold 段 f150-f210，目标是阻断 v10 这类右肘约 44°、肩到腕距离过短的假通过。

| 检查项 | 阈值 | 说明 |
|---|---|---|
| 右肘角 | 55°-100° | 小于 55° 说明前臂/上臂过度折叠，不符合稳定托下巴姿态 |
| 右肩到右腕距离 | 2.95-4.1 PMX | 距离过短会物理上迫使肘角掉到约 45° |
| 检查帧段 | f150-f210 | 只检查最终稳定段，不限制抬手过渡 |

修复原则：先把右腕放到“肩-腕距离约 3.1-3.4、腕-下巴距离约 2.3-2.5”的两球交集区域，再用右手首 Euler 和手型 profile 让指尖/掌侧靠近下巴。不要用“腕点贴脸”解决接触语义。

## G14 右手手型语义

G12/G13 证明右臂链条和下巴接触成立，但仍可能被“竖掌张开、指尖挡脸”的手型假通过。G14 只检查稳定 hold 段 f150-f210，用右手五指指尖和整手轮廓高度约束手型必须是半握托下巴，而不是张掌/爪形。

| 检查项 | 阈值 | 说明 |
|---|---|---|
| 五指指尖 Y 展开 | <= 0.30 PMX | 超限表示手指竖向张开，读作张掌/爪形 |
| 整手轮廓 Y 高度 | <= 1.13 PMX | 超限表示掌/指节整体竖起挡脸 |
| 最高右手代理点顶部余量 | >= 0.05 PMX | 最高点必须低于 G11 安全线至少 0.05 |
| 参与骨骼 | 右手首 + 右手所有指骨/指尖 | 使用 `rendered_bone_frames.json` |

修复原则：优先收拢 finger profile，尤其是导致最高点的小指/无名指关节；其次微调右手首 Euler。不要重新张开食指/中指来换取 G12 接触距离。

## 修复指引

每个 gate 失败时，程序输出会自动包含针对该 gate 的修复指引。以下是完整指引汇总。

### G1 坐标系完整性 (FAIL)

1. 检查 VMD 生成器是否有除零或 NaN 计算
2. 确认 BVH->PMX 坐标映射公式: `pmx = pmx_pelvis + (bvh - bvh_pelvis) * 8.54 * [1,1,-1]`
3. 检查骨骼段长度是否畸变 (上臂应≈3.0, 前臂≈2.6, 大腿≈5.2)
4. 在 gen_v9e.py 中添加 assert 对每帧关节坐标做 isfinite 检查
5. 排查 fk_world_model.py 的 FK 计算是否有 quaternion 归一化失败

### G2 骨骼位置合理性 (FAIL)

1. 检查骨骼是否超出解剖学范围 (头Y应17.5-22.5, 手腕Y应8-21, 踝Y应-1.5-4)
2. 确认 BVH->PMX 比例因子 8.54 是否正确 (torso scale)
3. 检查 IK 求解器是否把手腕目标设到了模型外部
4. 如果是 raise 阶段手腕过高: 降低 hold 目标 Y 值
5. 如果是脚踝漂移: 检查 IK 脚踝锁定是否启用

### G3 碰撞检测 (FAIL)

1. 手腕穿入腰部/胸部: 在 gen_v9e.py 的 `correct_arm_front_depth()` 中增加前向推力
   - raise 阶段: 手腕 Z 须 < -1.0 (躯干前表面)
   - 手腕在腰部范围 (Y 11.6-13.9) 时: 推 Z 到 -2.0 以下
   - 手腕在胸部范围 (Y 15.3-18.1) 时: 推 Z 到 -2.2 以下 (胸部前表面 Z=-2.11)
2. 肘穿入躯干: 在 fk_world_model.py 的 `apply_joint_limits()` 中限制肘外偏
   - 肘 X 不得进入躯干 X 范围 (|X| < 1.3 时需 Y < 13.9 或 > 18.1)
3. hold 阶段手贴脸: 允许头部穿透 0.8, 超过则降低手腕 Z 偏移
4. 使用 `/tmp/vertex_collision.py` 的 `is_inside_mesh()` 做精确顶点级碰撞检测替代 AABB
5. 在 Stage 5 优先级约束中: 碰撞约束为最高优先级, 违反碰撞时 IK 目标应回退

### G4 下巴接触距离 (WARN/FAIL)

1. 在 gen_v9e.py hold 阶段, 直接设定 IK 目标为下巴尖位置 `[0, 18.87, -1.41]`
2. 增大 push 偏移: `target_wrist_r += mul(front_pmx, 1.2)` (当前 0.95)
3. 检查 IK 求解器是否因臂展不足无法到达 (PMX 臂展 5.587, 目标距离可能超出)
   - 如超出: 启用 Stage 6 躯干前倾补偿增加可达范围
4. 下巴尖在头部网格内 (Z=-1.41, 头部前表面 Z=-1.97), 允许手腕穿入头部 0.5-0.8

### G5 关节角度限制 (FAIL)

**角度过小 (过度弯曲):**
1. 在 fk_world_model.py 的 `clamp_elbow_angle()` 中提高最小角限制
2. 肘最小角当前 20°, 思考动作建议提高到 60°
3. 检查 IK 求解器是否把目标设得太近导致手臂折叠

**角度过大 (过度伸直):**
1. 在 `clamp_elbow_angle()` 中降低最大角限制 (当前 175°)
2. 思考动作肘角应在 90°-130°, 限制 `max_elbow=140°`
3. 检查 IK 目标距离是否过远导致手臂伸直

通用: 在 `apply_priority_constraints()` 中, 关节限制优先级高于 IK 目标。

### G6 运动平滑度 (WARN)

1. 在 fk_world_model.py 的 `apply_motion_smoothing()` 中降低 `max_angular_velocity`
   - 上臂 0.25->0.15, 前臂 0.35->0.25
2. 增加平滑次数: 从 2 次提高到 3 次
3. 检查 VMD 帧间距是否不均匀 (BVH 20fps -> VMD 30fps 可能跳帧)
4. 在非均匀帧间距处使用自适应限速: `dt = frame_times[i] - frame_times[i-1]`
5. 加速度违规: 增加 jerk 限制
6. raise->hold 转折处抖动: 在阶段切换帧附近添加 3-5 帧缓动

### G7 左臂约束 (WARN)

**左手腕举过肩:**
1. 检查左臂是否被错误地镜像了右臂 IK 目标
2. 左臂不应应用下巴 IK 目标, 左臂应保持 T-pose 或自然下垂
3. 修复: `fabrik_two_bone_ik()` 调用时 `arm_side='left'` 不传入 chin target

**左手腕越过中线:**
1. 左手腕 X 应 > 0 (身体左侧)
2. 在 retargeter 中检查左臂 X 坐标是否被错误取反

**左肘弯曲:**
1. 思考动作左手应自然下垂, 肘角 150°-180°
2. 在 gen_v9e.py 中对左臂不施加 IK, 保留 BVH 原始旋转

例外: 如果 BVH 源动作本身左手有动作 (如双手动作), 此 gate 可配置为跳过。

### G8 前深度保持 (FAIL)

1. 在 gen_v9e.py 的 `correct_arm_front_depth()` 中:
   - raise 阶段: 手腕 Z 须 < -0.5 (front_depth > 0)
   - hold 阶段: 手腕 Z 须 < -1.0 (front_depth > 0.5)
   - 修正方式: `wrist_z = min(wrist_z, phase_threshold)`
2. 检查 front_axis 是否被错误地用了渲染空间值 `(0, 0.14, 0.99)`
   - PMX 空间应为 `(0, 0.14, -0.99)`, Z- = 前方
3. 如果 IK 求解后手腕向后偏: 检查 shoulder->elbow->wrist 运动链
   - 上臂向->前臂向的点积是否为正 (正=向前)

### G9 站姿稳定性 (WARN)

1. 脚踝位移超 0.3: 检查下半身 IK 是否锁定脚踝
2. 在 gen_v9e.py 中确保右足首/左足首骨骼旋转帧为全零 (不动脚)
3. 脚踝 Y 变化 (踮脚): 检查右足首D/左足首D 是否有错误旋转
4. 如果是全身平移漂移: 检查全ての親 (骨1) 是否有不需要的位移帧

### G10 FK/IK一致性 (WARN)

1. 在 fk_world_model.py 中检查 FABRIK 求解器收敛条件:
   - `max_iterations` 从 10 提高到 20
   - `tolerance` 从 0.01 收紧到 0.001
2. 检查 FK 模型是否使用了与 IK 相同的骨骼长度 (上臂 3.009, 前臂 2.578)
3. 如果 FK 手腕在 IK 目标后方: 检查 `fk_arm_chain()` 的旋转矩阵
   - 确认 `arm_side` 参数正确传递 (左/右臂偏移不同)
4. 在 gen_v9e.py 中, IK 求解后用 FK 验证, 如果偏差 > 1.0 则回退到上一帧

### G11 手部轮廓高度 (FAIL)

1. 降低右手 hold IK 目标 Y，降低量至少为 `worst_excess + 0.10 PMX`
2. 调整右手腕旋转，避免掌背/指节上翻造成视觉高点
3. 不要通过把手腕推到头后方来换取通过，G8 前深度仍必须通过
4. 重新渲染 `rendered_bone_frames.json`，确认右手腕和右手指骨/指尖都被导出
5. 重新运行 `motion_acceptance_gate.py --source render`，检查 G11 `total_violations == 0`

### G12 右手托下巴语义 (FAIL)

1. 如果右肘角 < 40°：右腕目标离肩太近，降低或前移右腕目标，扩大肩到腕距离。
2. 如果右腕到下巴距离 < 1.8：不要让腕点直接贴脸，改为让指尖/掌根代理点靠近下巴。
3. 如果最近手骨到下巴距离 > 0.85：先调右手首 Euler，再调 right-hand profile；最后才微调腕点。
4. 如果右肘 X < -2.6：右肘过度外翻，收回右肘 pole target。
5. 修复后必须重新生成四视角截图、GIF 和 `right_thinking_semantics_table.md`。

### G13 右臂解剖学自然度 (FAIL)

1. 如果稳定段右肘角 < 55°：腕点离肩太近，先把右腕移到肩-腕距离 >= 2.95 PMX 的区域。
2. 如果肩-腕距离 < 2.95：不要继续靠手腕大幅扭转补偿；需要重设右腕目标和右肘 pole target。
3. 如果肩-腕距离 > 4.1：右臂过度伸展，降低右腕外移/前移幅度。
4. 推荐搜索范围：右腕 PMX 约 `[0.2-0.5, 17.0-17.1, -3.2--3.1]`，再用右手首 Euler 和 soft/compact 手型调接触。
5. 修复后必须重新生成四视角截图、GIF、`right_arm_anatomy_table.md` 和 gate report。

### G14 右手手型语义 (FAIL)

1. 如果五指指尖 Y 展开 > 0.30：手指竖向张开，先收拢 right-hand profile。
2. 如果整手轮廓 Y 高度 > 1.13：掌/指节整体竖起，调整右手首 Euler 或降低腕点 Y。
3. 如果顶部余量 < 0.05：定位最高代理骨，优先收拢该手指；v12 中 `right_pinky_3` 过高时用 `chin_support` profile 收拢小指。
4. 不要通过放宽 G14 或重新张开手指来换取 G12 接触；正确做法是保留半握手型，再微调右腕目标。
5. 修复后必须重新生成四视角截图、GIF、`right_hand_shape_table.md` 和 gate report。

### G15 右手接近阶段安全 (FAIL)

1. 检查 f70-f130，接近下巴时必须保持收拢手型，不能以张掌或爪形扫过脸部。
2. 腕点距下巴 <= 3.60 PMX 时，指尖 Y 展开需 <= 0.50、整手 Y 高度 <= 1.22、平均指尖伸展 <= 1.62 PMX。
3. 如果失败，提前完成手指预弯，并把腕部翻转拆成多个方向关键帧，不要在贴脸前一帧突然翻掌。

### G16 下巴双点接触拓扑 (FAIL)

1. 稳定段拇指尖到下巴需 <= 1.10 PMX，食指尖到下巴需 <= 0.60 PMX。
2. 两个接触点间距需 >= 0.25 PMX，避免单点或重合代理点伪造托举语义。
3. 优先微调拇指/食指关节，再微调腕部 Euler；不要把整个腕点推进脸部。

### G17 腕部与掌面解剖 (FAIL)

1. 稳定段腕部弯折需 <= 55°，掌面法线到下巴方向夹角需 <= 70°。
2. 腕弯曲超限时先把旋转分配给 `右手捩`，掌面方向超限时再微调右手首 Y/Z 旋转。
3. 修复后必须从左右侧视角确认前臂、手腕和掌面连续，没有反折或穿脸。

2026-07-14 更新: v15 的腕弯曲为 59.5°，虽然低于旧上限 65°，但优菈厚袖口会放大折角，视觉上接近断腕。G17 上限因此收紧到 55°；v16 在保持右肘角 55.2°、肩腕距离 2.982 PMX 的前提下把腕弯曲降到 52.7°，并重新通过 G12-G18。

### G18 下巴接触锁定 (FAIL)

1. f150-f210 稳定段拇指和食指相对下巴漂移均需 <= 0.12 PMX。
2. 如果漂移超限，稳定段必须锁定腕、肘、头和躯干目标，不能叠加彼此不同相位的正弦摆动。
3. 保留呼吸感时应让整条接触链共享同一父级微动，而不是分别移动头和手。

## 验收流程

```
1. 生成 VMD → 运行 motion_acceptance_gate.py
2. gate 检查 G1-G18，输出 JSON 报告
3. P0 gate (G1/G2/G3/G5/G7[akimbo]/G8/G11-G18) 全部通过 + P1 gate 警告数 < 3 → 验收通过
4. P0 gate 有阻断 → 修复后重新生成
5. P1 gate 警告数 >= 3 → 评估是否可接受
```
