# Reze 着色器工作流

## 中文名称

Reze 着色器工作流。

## 英文机器名

`RezeShaderWorkflow`。

相关机器类型包括：

- `RezeMaterialStyleGroupId`：材质类别样式组标识；
- `RezeShaderGraphRef`：着色器图引用；
- `RezeShaderGraphAsset`：本地图资产；
- `RezeShaderGraphDraft`：编辑草稿；
- `RezeShaderApplyTransaction`：着色器异步应用事务；
- `RezeStageDocumentV2`：第二版 Reze 场景文档。

## 概念定义

Reze 着色器工作流是在 `reze-design` 与 `reze-k3` WebGPU 舞台中，以 MIT 许可的 `reze-engine` 公共 `ShaderGraph`（着色器图）、`StyleGroup`（引擎样式组）、`validateGraph()`（图校验）和 `compileGraph()`（图到 WGSL 的编译）接口为唯一执行边界，独立实现材质分类、图选择、用户级图库、节点编辑、编译提交和场景绑定的完整工作流。

该工作流把三个容易混淆的维度分开：

1. **材质类别样式组**负责组织 PMX 材质并提供推荐图，不限制用户可以选择的图；
2. **着色器图资产**负责保存可复用的图数据和渲染集成元数据；
3. **场景绑定**只保存样式组或单材质指向哪个稳定图引用，不复制图 JSON。

最终生效图按以下优先级解析：

1. 单材质图覆盖；
2. 当前样式组基线；
3. 标准类别推荐图；
4. 未分组材质的引擎中性回退。

人工移动材质只改变其所属样式组，不清除单材质图覆盖。没有单材质覆盖时，材质在移动后跟随新组基线。

## 解决的问题

当前实现只有不完整的样式组集合和同步外观接口。页面调用 `setMaterialPreset()` 后会立即更新勾选与 localStorage，但 WebGPU 运行时实际通过未等待的 `engine.upsertStyleGroup()` 异步编译并安装管线，因而可能出现“界面与存档显示已应用，舞台仍是旧图或编译已经失败”的错误提交。

当前 `materialPresets` 同时承担组批量赋值和单材质覆盖，无法表达：

- 样式组自己的基线图；
- 单材质是否显式覆盖；
- 材质是否被人工移动到另一类别；
- 本地图资产与场景引用的分离；
- 节点编辑中的草稿、临时预览和正式应用边界。

本概念通过显式的绑定层、用户级图库仓储和异步提交事务解决这些歧义，同时保持旧场景可迁移、编译失败可回退、多个快速请求只接受最后一次结果。

## 适用场景

- `reze-design` 与 `reze-k3` 的九类内置着色器图选择和材质组织；
- 样式组快速选择器、单材质覆盖、材质跨组移动；
- 本地自定义着色器图的导入、导出、收藏、复制、删除和跨模型复用；
- 基于当前 `NODE_REGISTRY` 的可视化节点编辑；
- 需要等待 WebGPU 编译结果后再更新界面和场景文档的提交操作；
- v1 Reze 场景文档向 v2 的兼容迁移。

## 不适用场景

- 不把 AGPL-3.0 的 `reze-design` 编辑器源码复制、改写或纳入当前项目；
- 不用于 `classic`、`hero-shot`、`genshin`、`mio-reference`、`k3` 或 `reze-npr` 的 Three.js 材质执行；
- 不负责社区发布、云端同步、跨设备同步、多人协作或云端版本历史；
- 不改变 PMX、VMD、IK、Grant solver、物理、动作状态机或动作验收 Gate；
- 不把图拓扑 SVG 当作真实渲染缩略图；真实视觉仍由 MMD 舞台预览。

## 核心不变量

1. 标准材质类别固定为默认材质、角色皮肤、眼睛、面部、头发、金属、粗糙布料、柔滑布料、丝袜九类，另有未分组。
2. 类别样式组只负责组织和推荐，不限制可选择的着色器图；任意内置或可应用本地图都可绑定到任意非空组或单材质。
3. 内置图的持久标识使用既有中文名称；英文名称只用于显示和元数据。
4. `默认`是实际的 Principled BSDF 图，不表示继承；`跟随样式组`只表示删除单材质图覆盖。
5. 样式组基线变化不得覆盖已有单材质图覆盖。
6. 人工材质分组覆盖与单材质图覆盖相互独立；恢复自动分组不得清除图覆盖。
7. 场景文档只保存稳定图引用与绑定关系，不保存本地图的 `ShaderGraph` JSON。
8. 本地图资产按 `userId` 隔离存入 IndexedDB；内置图只读，不写入 IndexedDB。
9. 编辑器始终操作本地草稿。打开内置图或已可应用的本地图进行编辑时，必须创建独立草稿，不能在编辑过程中改变当前场景绑定。
10. 同步 `validateGraph()` 与 `compileGraph()` 只完成图结构校验和 WGSL 生成；正式舞台提交必须等待引擎异步创建并安装 WebGPU 管线。
11. 编译期间旧图继续渲染。只有引擎返回成功、请求仍是该目标最新世代、目标模型仍一致且场景文档写入成功时，界面勾选和正式绑定才可提交。
12. 编译失败、持久化失败、目标失效或请求被更新请求取代时，不得保留新的正式绑定；舞台恢复最后一个成功且已持久化的图，并向用户展示可定位到阶段或节点的诊断。
13. 删除仍被任一场景文档引用的本地图前，必须列出引用并要求选择替代图；不得静默删除或留下悬空引用。
14. 旧 `半透材质` 只迁移为 `柔滑布料`，不得迁移为 `丝袜`；新菜单和新导出不得再产生 `半透材质`。
15. `stocking`、`socks`、`tights`、`丝袜`等丝袜提示必须先于 body/skin 规则判断，避免丝袜误归角色皮肤。
16. 当前 `reze-engine@0.26.0` 的节点注册表包含 40 种节点类型；编辑器必须由注册表驱动覆盖，不得把节点数量硬编码为旧的“约 25 种”。
17. 图结构继续服从引擎公共约束：`ShaderGraph.version=1`、最多 64 个节点、最多 16 个暴露参数、节点 ID 符合 `/^[a-z0-9_]+$/`，最终输出必须可解析为颜色或浮点值。
18. 三栏图库打开后应用目标必须锁定；浏览、筛选或查看详情不得悄悄切换目标。模型切换或目标消失时必须关闭或显式失效该目标。
19. “重置此材质”清除单材质图覆盖和会话级临时显隐，但保留人工分组覆盖；“恢复自动分组”只清除人工分组覆盖；“恢复全部默认”不改变灯光、相机、背景或人工分组。
20. `reze-design` 与 `reze-k3` 使用相同工作流和数据契约，但场景文档仍按 `userId + modelPath + pipeline` 隔离，不能跨管线覆盖。

## 证据或计算口径

- 当前场景文档版本为 1，使用 `materialPresets` 保存按材质键分配的中文预设。
- 当前 WebGPU `setMaterialPreset()` 调用 `void engine.upsertStyleGroup()` 后立即返回，页面随即更新 UI 与 localStorage；该调用顺序证明提交边界尚未等待编译。
- `reze-engine` 的 `upsertStyleGroup()` 返回 `ApplyStyleGroupResult`，包含 `ok`、`diagnostics` 和 `slotMap`；引擎在图编译、WGSL 编译或管线创建失败时不替换既有安装。
- 引擎对同一 `StyleGroup.id` 已有世代号保护，但宿主仍需按用户操作目标维护最新请求世代，避免过期结果更新 React 状态或持久化。
- 当前 `NODE_REGISTRY` 实际包含 40 个键；`MAX_NODES=64`、`MAX_PARAMS=16`。
- 当前内置图共九个：默认、角色皮肤、眼睛、面部、头发、金属、粗糙布料、柔滑布料、丝袜。
- 当前 PMX 材质键由运行时提供并被场景层视为不透明稳定键；现有实现中可能是 `reze:material:<序号>` 或 `mesh:<遍历序号>:material:<槽位>`，场景层不得解析其内部含义。

## 正例

用户从面部样式组的快速选择器选择金属图。界面显示“编译中”，舞台继续使用原面部图。编译成功且该请求仍是最新请求后，舞台切换为金属图，快速选择器勾选金属，并把面部组基线写入 v2 场景文档；面部组中已有的单材质覆盖保持不变。

用户打开一个内置头发图进行编辑。系统创建新的本地草稿；用户修改节点后，约 300ms 防抖触发校验和临时预览。关闭且未应用时舞台恢复进入编辑器前的图，草稿仍保存在当前用户的本地图仓储中。

用户把丝袜材质人工移动到角色皮肤组，但该材质已有单材质丝袜图覆盖。移动后材质仍使用丝袜图；点击“跟随样式组”后才清除覆盖并改为跟随角色皮肤组基线。

## 反例

- 把当前选中的图在点击瞬间写入 localStorage，再异步尝试编译；
- 把“默认”选项解释为跟随样式组；
- 切换组基线时批量覆盖所有单材质覆盖；
- 编辑一个已被多个场景引用的本地图时直接改写其图 JSON；
- 删除被引用的本地图而不列出引用；
- 复制 AGPL 参考编辑器组件源码；
- 将拓扑 SVG 描述为材质真实效果预览；
- 继续把 `半透材质`显示为新建或导出选项；

均不符合本概念。

## 失败后的修正路线

1. 如果 v1 场景迁移失败，保留原 v1 键和值，停止写 v2，并展示可复制的迁移错误；不得覆盖旧值。
2. 如果图结构校验失败，定位到 `Diagnostic.nodeId` 对应节点，修正节点、插槽、链接、循环或参数目标后重新校验。
3. 如果 WGSL 或 WebGPU 管线编译失败，保留最后成功图和场景绑定，显示引擎诊断；不得用默认图冒充提交成功。
4. 如果快速连续选择出现旧结果覆盖新结果，检查目标世代号、引擎组 ID 稳定性和 React 提交条件。
5. 如果材质移动后样式异常，分别检查人工分组覆盖、单材质图覆盖和组基线，不得通过清空全部状态掩盖优先级错误。
6. 如果删除图时引用列表不完整，扫描当前用户全部 v2 场景文档；任何文档无法解析时应保守阻断删除。
7. 如果节点注册表新增类型而编辑器缺少支持，节点目录覆盖测试必须失败；补全中文元数据和通用属性控件后再发布。
8. 如果窄屏或矮窗口控件重叠，保持舞台、图库列表、详情和材质树各自独立滚动，不得以固定大高度或隐藏控件规避。

## 与现有概念的关系

本概念建立在 `workflow/concepts/reze-design-stage.zh-CN.md` 的 Reze 舞台配置之上。Reze 舞台概念定义渲染管线、场景、背景、模型和动作边界；本概念只定义 WebGPU 材质着色器图的组织、资产、编辑、提交和持久化边界。

它不废弃现有 `materialPresets` 数据，而是通过 v1→v2 迁移将其重新解释为单材质图覆盖。现有场景、调色、背景和相机字段继续保留。
